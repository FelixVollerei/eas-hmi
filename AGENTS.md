# Development rules

State the user goal and current scope briefly, then work. Reversible code changes and
focused tests within that scope need no repeated per-file registration or admission.
Keep one concise task note, actual test results and a reversible Git commit when requested.
Ask for authorization when required for high risk, expanded scope, external publication,
real user data, credentials or security settings. Keep product authorization checks intact.
Use focused tests for small changes and necessary independent review for larger changes.
Preserve other contributors' changes. Never upload user data, credentials or build caches.
