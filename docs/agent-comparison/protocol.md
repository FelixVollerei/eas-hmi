# EAS-HMI 与视觉操作 Agent 的配对实验（尚未执行）

题目：**冷却系统画面的批量位置调整、局部尺寸修改与标题修订**。

目的：在相同模型、同一初始画面和相同目标下，比较语义 CLI 与截图/鼠标/键盘操作的工程正确性、Agent 成本和耗时。实验使用合成的 672 节点工程，cooling 画面含 493 节点，20 个泵卡片。该实验不能证明所有 HMI 任务的优劣。

## 任务与边界

两组都将 CHWP-01 至 CHWP-20 的**卡片本体及其子图形**相对原位置右移 12、下移 8 个模型单位；仅 CHWP-07 卡片宽度改为 164，高度保持原值；画面主标题改成 `COOLING / REVIEWED`。其他对象、连接线的位置和所有绑定保持不变。不要移动整个泵分组，因为其中还包含不应移动的连接线。

不在提示词中提供每个对象的坐标、答案文件、评分脚本实现或旧 Demo 的解题调用记录。两组提供相同的可见标签与任务说明。CLI 组可以通过语义查询发现稳定 ID；视觉组可以通过画面、对象面板和属性栏定位对象，这是被比较的接口差异。

主实验不包含绑定修复：普通 Inkscape 没有点表绑定面板。若以后使用有绑定面板的传统 HMI 编辑器，可以另设“补齐 3 个 fault 绑定”扩展任务，两边须先导入完全相同的点表、模板规则与模型。扩展项单独报告，不能把编辑器不支持的功能计入主实验失败率。

## 运行前准备（由评估者执行，不计 Agent 时间）

1. 固定模型版本、推理强度、上下文/工具预算、电脑、显示缩放、窗口大小、Inkscape 版本、网络条件及工具权限。关闭无关负载。两组各用全新任务，没有本项目开发记录或其他组的答案。工具安装与学习材料预先就绪。
2. 在项目根目录执行 `python scripts/agent_trial.py prepare --output D:/EAS-Trials/pair-01`。目录必须不存在。复制 seed 到评估者私有目录；记录文件 SHA256。该命令只准备数据，不运行 Agent。
3. CLI 组只能看自己的 `semantic-project`、一份 CLI 使用说明和该组 prompt；视觉组只能看打开的 `visual-input.svg`、Inkscape 普通帮助和该组 prompt。评分脚本、oracle 和另一组目录应在 Agent 无权限读取的位置；不要只依赖一句禁止访问。
4. **先由评估者验证兼容性**：在另外的预检副本中，用约定版本 Inkscape 完成一次普通保存、平移、改宽与标题修改，确认产生的 SVG 可以被 `sync-from-svg --dry-run` 接受。不要把预检答案给参赛 Agent。这里没有宣称已做过这项真实 GUI 预检。
5. 如果普通 Inkscape 保存会触发不支持的 SVG，记录为接口集成问题，先处理适配或重新预注册仅含已支持操作的题目，再开始正式实验。不能在看到两组结果后更改评分。正式运行若发生集成错误，保留失败记录；工程完成率为失败，图形任务分数记 NA，不擅自推断视觉能力为零。
6. 视觉组进入同一个缩放比例，完整显示 cooling 页面，任何属性/对象窗口均处于预先登记的固定状态。CLI 组初始 revision=0。输出均为 `result.svg`。EAS 组也必须交付 SVG，由**同一个**评估器解析两组文件。

## 两套提示词

直接使用同目录的 `prompt-semantic.md` / `prompt-visual.md`，只替换尖括号中的目录。每个任务限 20 分钟及 120 次底层工具调用；达到任一上限立即保存当前结果并停止。若要改预算，必须在两组开始前统一修改并登记。

建议先做 1 对探索性运行，不作优劣结论；正式至少 5 对，顺序交替 A→B / B→A。每次重新准备原始数据，不接着前一轮改。保持模型和预算一致。随机种子不可控制时明确记录；5 对仍只能作为探索性证据。

## 计量定义

| 指标 | 定义与记录来源 |
|---|---|
| 总墙钟时间 | 从提交完整 prompt 到 Agent 最终答复；包括观察、推理、工具等待与失败恢复，排除安装和评估者准备 |
| 活跃时间 | 若人工暂停/权限等待，额外单列暂停时长；墙钟总时间不能悄悄减去这些时间 |
| 输入/输出 token | 优先导出运行平台或 API 的真实 usage；cached input 单列且通常是 input 的子集；reasoning token 通常是 output 的子集，勿重复相加 |
| 图像 token | 使用平台实际计费/usage；不知道就填 NA，不能用截图张数或字符数换算冒充实测 |
| 总 token | input + output，前提是平台定义不重叠；没有真实 usage 则填 NA。账户用量百分比不能换算单任务 token |
| 工具步数 | 统计底层工具调用数。一次包装调用里执行 5 个 CLI 命令计 5；一次脚本封装 20 次点击计 20 个动作，另报包装调用数 |
| 观察/动作 | 分别记录 screenshot、UI 状态读取、CLI 读取、CLI 写入、click/type/scroll/hotkey、失败调用。一次批量语义命令计 1 个命令，影响的对象数量另列 |
| 正确性 | 下表 0–100 分；同时报告 complete_success、非目标改动数、集成失败率、人工介入次数 |

记录原始轨迹，不让 Agent 自报“用了多少 token”。用 `run-ledger.json` 的模板逐次填实测值。NA 与 0 必须区分。中断/崩溃/超时不删除、不自动重跑覆盖原记录；若重跑，产生新的 run_id 并标明原因。

## 评分（预注册）

| 项目 | 分值 | 判定 |
|---|---:|---|
| 20 张卡片平移 | 40 | 每张 2 分；x、y 均在期望位置 ±0.5 模型单位内才得分 |
| CHWP-07 宽度 | 10 | 宽度 164 ±0.5；其余尺寸由保留项检查 |
| 标题 | 10 | 文本严格等于 `COOLING / REVIEWED` |
| 非目标状态保留 | 30 | 从 30 起，每个额外变化的语义对象扣 5，最低 0；包括绑定、父级、连接、样式、其他页等 |
| 文件可用 | 10 | 交付 SVG 被同一同步器完整解析且可以入模 |

输出缺失：工程任务失败、0 分。SVG 不兼容：集成失败、图形分 NA、完整成功=false，保留原因；总成功率分母仍包含该轮。完整成功要求全部目标正确且没有额外语义变化，不能仅凭总分高就算完成。

评估者对两组都执行：

```powershell
python scripts/agent_trial.py score --seed D:/EAS-Trials/pair-01/seed.json --svg <该组result.svg> --output <该组score.json>
```

评分器只读取交付文件，不修改工程。默认读取“原 seed + 交付的 cooling SVG”恢复整工程，检查不可见的绑定等语义状态。它不负责判断画面美感。GUI 兼容性预检是正式实验的前提。

## 最后比较

逐对报告分数、完整成功、总时间、input/output/cached/reasoning token、工具命令数和 UI 动作数。汇总中位数及每轮原始值，给出配对差值；样本很少时不要作显著性结论。未成功/NA 的轮次也展示，不能只比较成功样本的速度。token/正确完成任务与耗时/正确完成任务只作附表，不用“分数÷token”掩盖错误。

结论应限于这个题目、编辑器、模型和机器。**本次交付没有执行两组 Agent 实验，也没有填任何胜负或 token 数。**
