# EAS-HMI 分阶段实施计划

依据：`requirements-original.txt`。采用用户评估时的六个阶段。
执行规则：每阶段完成后提交验收报告并结束该次工作，收到用户继续指令才进入下一阶段。
阶段完成不等于整个 MVP 已完成；设计文档不能替代功能测试。

| 阶段 | 工作内容 | 退出条件 | 当前状态 |
|---|---|---|---|
| 1：建立验收矩阵 | 需求映射到模块、命令、测试、交付物；固定坐标、ID、同步、错误策略 | 逐项有验证方式，形成设计约定和报告 | 完成 |
| 2：优先验证难点 | 小样本验证矩阵同步、opaque 依赖、无修改往返、PNG/BMP | 高风险路径实测通过，确认支持范围及栅格化后端 | 完成，见 stage-2-report.md |
| 3：打通最小闭环 | Model → CLI → 校验 → 事务 → history/diff/undo → render → sync | 编辑可追踪可撤销，失败无部分提交，故障恢复通过 | 完成，见 stage-3-report.md |
| 4：补齐完整功能 | 全部节点、模板、查询、局部上下文、批量、导入、清单、事件流 | 所有必需命令有成功/失败用例 | 完成，见 stage-4-report.md |
| 5：建立合成 Demo | 三页面、规定设备数量、500+ nodes、300+ points、错误 fixtures | Task A–G 从头成功，执行记录及产物可复核 | 完成，见 stage-5-report.md |
| 6：最终验收 | 干净环境安装、pytest、覆盖率、Demo、校验、渲染、导出、性能、README | 逐项实测，交付最终报告并明确未完成项 | 完成，见 stage-6-report.md |

## 工作目录与边界

- 独立项目 `D:\Codes\eas-hmi`，使用专属 `.venv`，不向现有 Anaconda 全局环境装依赖。
- 设备、点表、图形全部合成；现有 AVEVA 工程不是输入，不更改其文件。
- CLI 是 Agent 编辑接口，无 GUI/OCR/截图理解/模型 API 集成。
- 不增加 Web、MCP、自定义通信协议、数据库服务、工业运行控制。
- GitHub 连接/远端尚未验证，本阶段没有远程发布动作；远端不是 MVP 的验收前提。

## 实施与测试原则

每阶段先准备相应测试和少量 fixtures，再实现最小能力，运行验证并报告限制。
失败在当前阶段修正；不能以未来承诺替代当前退出条件。
已有代码草稿不等于相应阶段通过。

- pytest 覆盖率最终对整个 `src/eas_hmi` 包统计，目标 >=85%。
- 不通过排除困难核心代码或无意义测试提高覆盖率。
- 验证状态、引用、文件格式/尺寸、确定性及历史一致性。
- 人编辑模拟与实际 Inkscape 保存兼容性证据分开，前者不证明任意 Inkscape 操作兼容。
- 非法 fixtures 独立可重建，不通过正常事务将 ERROR 状态写入主 Demo。
- 完整 Demo 用 subprocess 调实际 CLI，记录命令及结构化结果。

## 阶段报告

每份报告包含范围、结论、交付物路径、实际验证及退出码、未验证/失败项、
偏差与风险、下一阶段入口，并明确停止，不自动进入下一阶段。
