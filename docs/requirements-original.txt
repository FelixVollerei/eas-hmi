# EAS-HMI MVP

你需要直接实现一个可运行的实验项目。

项目暂定名：

**EAS-HMI — Engineering Agent Sidecar for HMI**

它的目的不是开发一个新的 HMI 软件，也不是开发通用桌面 Agent，而是验证：

> 对于传统 HMI / SCADA 工程制作工作流，如果给 AI Agent 一个结构化、可查询、可修改、可验证的工程语义通道，是否可以显著减少 AI 对截图、视觉理解、鼠标键盘和原始 SVG/XML 文本编辑的依赖。

本阶段目标是优化如下真实工作流：

AI/工程师制作 SVG  
→ Inkscape 调整  
→ 导出图形资产  
→ 后续导入工业 HMI/SCADA 软件  
→ 人工完成变量绑定等组态工作

V1 不直接操作 AVEVA Plant SCADA。

重点完成：

**structured engineering model + semantic SVG + Agent CLI + validation + human edit synchronization + export manifest**

---

# 1. 核心设计原则

必须始终遵守：

## 1.1 Canonical Model 是唯一工程事实来源

系统内部维护一个结构化 HMI 工程模型。

SVG 是 Human View / interchange representation。

Codex / Agent 不应通过分析屏幕像素理解工程，也不应以直接修改大型 SVG/XML 文本作为主要工作方式。

正常 Agent 工作流必须是：

Agent intent

→ CLI structured command

→ transaction

→ model modification

→ validation

→ commit

→ SVG render

---

## 1.2 Human 与 Agent 操作同一份工程状态

Agent：

CLI → Canonical Model

Human：

Canonical Model → semantic SVG → Inkscape

如果 Human 使用 Inkscape 修改 semantic SVG，则必须通过显式：

`eas-hmi sync-from-svg`

把支持的修改重新同步回 Canonical Model。

不要建立两个自动竞争的 Source of Truth。

---

## 1.3 Pixels are for humans; semantics are for agents

系统不得要求 Agent：

- OCR
- screenshot recognition
- mouse automation
- keyboard automation
- screen coordinate reasoning

MVP 的完整 Demo 中不得使用以上能力。

---

## 1.4 Deterministic work belongs to deterministic code

以下工作不得让 LLM 一项一项推理完成：

- 批量移动对象
- 批量修改尺寸
- 查找绑定
- 对齐
- 分布
- 查询引用关系
- 检查缺失字段
- 重复 ID 检查
- point reference 检查
- SVG 生成
- diff
- undo

这些必须由本地程序完成。

LLM 只负责表达工程意图和处理异常。

至少：

- name
- version
- canvas defaults
- pages
- equipment registry
- point registry
- templates
- metadata

至少：

- id
- name
- width
- height
- background
- nodes
- metadata

支持典型 1920×1080 等分辨率，但不能硬编码。

## Node

- id
- kind

## Equipment

至少：

- id
- name
- type
- system
- parent
- metadata

## Point

至少：

- id

- datatype
- unit

- metadata

## Binding

不要简单地把 binding 存成任意字符串。

至少明确：

- point_ref

- command

# 6. Component / Template Binding Requirements

实现一个轻量模板定义。

例如：

pump template 可以声明：

required_bindings:

- run
- fault

optional_bindings:

- local
- remote

sensor template：

required_bindings:

- value

这样：

`eas-hmi validate`

可以进行语义检查，而不仅仅做 JSON Schema 检查。

# 7. Opaque SVG

这是 MVP 的关键要求。

现实 SVG 中存在大量：

- path
- gradient
- clipPath
- mask
- complicated icon geometry
- Inkscape specific metadata

Agent 不需要理解这些细节。

系统必须允许：

```text
opaque_svg
```

节点。

opaque_svg：

- 保存原始 SVG fragment 或安全引用
- Agent 可以移动
- 缩放
- 旋转
- 设置 visible
- 赋予 semantic ID
- 绑定 equipment
- 添加 metadata

但不得因为 importer 不理解内部 path 就删除或重建它。

目标是：

**preserve first, understand later**

---

# 8. Semantic SVG

Renderer 生成的 SVG 必须保留稳定的语义标记。

例如：

```xml
<g
    id="node-CHWP_CARD_01"
    data-eas-id="CHWP_CARD_01"
    data-eas-kind="equipment_card"
    data-eas-equipment="CHWP_01">
```

如果有 binding，可以使用合理的数据属性记录引用 ID。

不要把所有 Canonical Model JSON 整份塞进 SVG attribute。

SVG 应只包含：

- 对 round-trip 必要的数据
- object identity
- object type
- equipment reference
- 必要 synchronization metadata

Canonical Model 仍是主数据。

---

# 9. SVG Import

实现：

```bash
eas-hmi import-svg input.svg
```

目标不是完美理解所有 SVG。

Importer 应：

1. 解析 SVG；
2. 已有 `data-eas-*` 对象恢复为 semantic node；
3. 普通复杂 SVG group/path 无法识别时，可以转成 opaque_svg；
4. 保留原始视觉内容；
5. 为未标识的重要顶层对象生成稳定 ID；
6. 创建 Canonical Model；
7. 不修改原始输入文件。

禁止：

因为无法理解某 SVG feature 就静默丢弃。

无法支持时必须：

- preserve as opaque
或
- 明确 warning

---

# 10. Render

实现：

```bash
eas-hmi render
```

Canonical Model

→ semantic SVG

要求：

- 输出稳定
- 相同 model 多次 render 应产生确定性结果
- ID 必须稳定
- semantic metadata 必须稳定
- 不因为 render 改变 model

# 11. Inkscape Human Editing Round Trip

这是 MVP 的高优先级功能。

工作流：

```text
model
↓
render
↓
semantic SVG
↓
user edits with Inkscape
↓
eas-hmi sync-from-svg edited.svg
↓
structured diff
↓
transaction
↓
model
```

实现：

```bash
eas-hmi sync-from-svg <file>
```

V1 至少识别：

- tagged node translation
- x/y
- width/height
- rotation
- text content
- visibility

如果 Inkscape 使用 transform matrix，应尽量解析常规：

translate  
scale  
rotate

如果无法安全转换某项编辑：

不得猜测。

报告：

```text
UNSUPPORTED HUMAN EDIT
node=...
attribute=...
```

Opaque 图形内部艺术修改允许被保存，但必须明确：

这些修改属于 opaque payload，不强制投影为结构化属性。

# 14. Transaction

每次编辑应执行：

```text
Load
↓
Check revision
↓
Create candidate change
↓
Validate affected objects
↓
Validate project invariants
↓
Commit
↓
Write history
↓
Render if enabled
```

如果 validation 出现 ERROR：

整个 transaction 必须 rollback。

WARNING 是否阻断由规则决定。

不得出现：

部分对象成功修改、部分失败，但 CLI 返回 success。

---

# 16. Diff

实现：

```bash
eas-hmi diff
```

默认显示最近 transaction。

以及支持 JSON：

```bash
eas-hmi diff --json
```

Diff 必须以 semantic object 为单位。

不要只返回 raw JSON textual diff。

例如：

```text
CHWP_CARD_01

420 → 460

bindings.fault:
null → CHWP01_FLT
```

# 17. Undo

实现：

```bash
eas-hmi undo
```

要求：

最近 transaction 可以完整撤销。

Undo 后：

Canonical Model 的语义状态必须与该 transaction 前一致。

为测试提供 canonical hash 方法。

---

# 18. Validation

实现：

```bash
eas-hmi validate
```

必须至少检查：

### Structural

- schema validation
- duplicate IDs
- invalid node parent
- invalid page reference
- invalid equipment reference
- invalid point reference
- circular hierarchy

### Geometry

- negative width
- negative height
- NaN / Infinity
- node outside page bounds

out-of-bounds 可以配置为 WARNING 或 ERROR。

### Binding

- point does not exist
- binding role violates template rules
- required binding missing
- duplicate incompatible bindings

### Semantic

- equipment ref exists
- equipment hierarchy valid
- node ID uniqueness
- template ref validity

返回：

```text
ERROR
WARNING
INFO
```

并支持 JSON。

每条 issue 必须有：

- code
- severity
- object_id
- message
- suggested_action，可选

---

## Agent-native

完整 demo 中：

- screenshot count = 0
- OCR calls = 0
- mouse actions = 0
- keyboard GUI actions = 0

所有工程理解来自：

- structured model
- query
- inspect
- context
- validation
- event/diff

---

## Safety / Correctness

任何 write command：

- 必须 transaction 化
- validation error 时不得 partial commit
- 必须留下 operation history
- 必须可定位 affected IDs

---

## Round-trip

对于项目自身 renderer 输出的 semantic SVG：

render  
→ sync-from-svg without modification

必须：

- 不产生 semantic changes
- model canonical hash 保持一致

对支持的人类修改：

- translation
- resize
- rotation
- text edit
- visibility

必须正确产生 structured operation。

---

## Determinism

相同 Canonical Model 连续 render：

应产生语义等价且规范化稳定的 SVG。

如果可以做到 byte-identical，应做到 byte-identical。

---

## Performance

在 synthetic project 至少：

- 500 visual nodes
- 300 points

情况下：

正常 query 和 validation 不得有明显交互延迟。

不要做过早微优化，但不得每个 query 调 LLM 或完整 rasterization。

# 28. Important Engineering Decisions

遇到设计选择时优先级：
